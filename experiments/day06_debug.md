# Day 06：训练过程调试与实验分析

## 一、实验目标

通过人为制造训练异常，理解 PyTorch 训练过程中梯度累积和学习率对模型训练的影响，掌握控制变量实验方法。

## 二、实验一：删除 optimizer.zero_grad()

### 1. 实验修改

在 `train_one_epoch()` 中删除：

```python
optimizer.zero_grad()
```

其他训练条件保持不变。

### 2. 实验结果

| Epoch | Train Loss | Train Accuracy |
|---|---:|---:|
| 1 | 1.2445 | 65.62% |
| 2 | 1.7584 | 41.21% |
| 3 | 2.2052 | 25.71% |
| 4 | 2.2740 | 19.18% |
| 5 | 2.3436 | 11.03% |

测试集：

- Test Loss：2.3631
- Test Accuracy：11.35%

### 3. 原因分析

PyTorch 默认会累积梯度。

正常训练流程：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

如果删除 `optimizer.zero_grad()`，每个 Batch 计算出的新梯度就会累加到之前已有的梯度上。

例如：

- Batch 1：G1
- Batch 2：G1 + G2
- Batch 3：G1 + G2 + G3

随着 Batch 不断增加，梯度会持续累积，导致参数更新偏离正常训练过程。

需要注意：

- `backward()`：计算梯度，默认累积到 `.grad`。
- `step()`：根据梯度更新参数，不负责清零。
- `zero_grad()`：清空梯度。

另外，Train Loss 的统计变量每个 Epoch 都会重新初始化，因此这里出现的问题不是 Loss 数值本身跨 Epoch 累加，而是梯度累积导致模型参数更新异常。

### 4. 实验结论

训练过程中应该正确管理梯度。通常每个 Batch 更新参数之前，先清空上一批次的梯度，避免意外累积。

## 三、实验二：学习率过大（LR=0.1）

### 1. 实验修改

恢复 `optimizer.zero_grad()`，将 Adam 的学习率从 0.001 修改为 0.1。

其他条件保持不变。

### 2. 实验结果

| Epoch | Train Loss | Train Accuracy |
|---|---:|---:|
| 1 | 2.4761 | 10.36% |
| 2 | 2.3203 | 10.24% |
| 3 | 2.3142 | 10.35% |
| 4 | 2.3152 | 10.19% |
| 5 | 2.3143 | 10.26% |

测试集：

- Test Loss：2.3171
- Test Accuracy：9.58%

### 3. 原因分析

梯度下降的基本更新公式：

\[
\theta_{new}=\theta_{old}-\eta\nabla L(\theta)
\]

其中：

- \(\theta\)：模型参数。
- \(\eta\)：学习率。
- \(\nabla L\)：损失函数的梯度。

学习率决定参数每次更新的步长。

学习率过大时，参数更新可能跨越较好的优化区域，造成训练不稳定，无法有效收敛。

MNIST 有 10 个类别，随机猜测的准确率约为 10%。

当模型对 10 个类别的预测概率近似均匀时：

\[
Loss=-\ln(0.1)\approx 2.3026
\]

本次实验 Loss 长期维持在 2.31 附近，Accuracy 约为 10%，说明模型基本没有学到有效的分类规律。

### 4. 实验结论

学习率过大可能导致模型无法正常收敛，甚至表现得接近随机猜测。

## 四、实验三：调整学习率（LR=0.01）

### 1. 实验修改

将学习率从 0.1 降低到 0.01，其他条件保持不变。

### 2. 实验结果

| Epoch | Train Loss | Train Accuracy |
|---|---:|---:|
| 1 | 0.2825 | 92.17% |
| 2 | 0.1873 | 95.10% |
| 3 | 0.1589 | 95.88% |
| 4 | 0.1419 | 96.30% |
| 5 | 0.1299 | 96.70% |

测试集：

- Test Loss：0.1650
- Test Accuracy：96.05%

### 3. 原因分析

将学习率从 0.1 降低到 0.01 后，参数更新步长减小，模型能够更加稳定地学习。

从结果可以看出：

- Train Loss 持续下降。
- Train Accuracy 持续上升。
- Test Accuracy 达到 96.05%。
- 训练集和测试集的表现比较接近。

说明当前学习率下，模型恢复了正常的学习能力。

### 4. 实验结论

学习率并不是越大越好，也不是越小越好，需要结合模型、优化器和数据集进行实验。

## 六、训练异常的综合分析

### Q1：删除 optimizer.zero_grad() 后，为什么训练效果越来越差？

因为 PyTorch 默认累积梯度，删除梯度清零操作后，每个 Batch 的梯度会不断累加，导致参数更新异常。

### Q2：学习率过大为什么导致模型无法正常收敛？

因为学习率决定每次参数更新的步长。学习率过大时，参数可能不断越过较好的优化区域，无法稳定收敛。

### Q3：Train Loss 很低，但是 Test Loss 很高，可能是什么问题？

可能是过拟合（Overfitting）。

模型过度学习训练集中的特征甚至噪声，在训练集上表现很好，但泛化到测试集时表现较差。

### Q4：Train Loss 和 Test Loss 都很高，可能是什么问题？

可能是欠拟合（Underfitting），也可能是优化失败。

常见原因包括：

- 模型容量不足。
- 训练时间不够。
- 学习率设置不合理。
- 数据预处理存在问题。
- 模型或训练代码存在错误。

需要结合训练曲线和实验情况进一步判断。
